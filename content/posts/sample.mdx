This page is a working specimen of the article layout. It brings together the elements that appear in technical writing, from a short `git status` command to wide tables and nested code blocks.

## Typography and inline code

A paragraph should be easy to follow without competing with the navigation. **Strong text** adds emphasis, _italic text_ adds a quieter distinction, and [links remain easy to identify](https://astro.build). A footnote can carry a useful aside without interrupting the sentence.[^layout]

Inline code such as `pnpm run build`, `config.enabled`, and `/etc/loader/loader.conf` should sit comfortably within the line. Longer identifiers such as `a_deliberately_long_configuration_key_that_needs_to_wrap_on_a_small_screen` must stay inside the reading column.

### Third-level heading

Use this level to break a section into related ideas. The spacing should make the hierarchy clear without adding another box around every paragraph.

#### Fourth-level heading

Smaller headings remain neutral rather than introducing another accent color.

##### Fifth-level heading

A compact label for a small subdivision.

###### Sixth-level heading

The final heading level should still be readable without becoming louder than the paragraph around it.

## Lists and tasks

- Understand the workflow before changing it.
  - Identify the repeated steps.
  - Write down what a successful run looks like.
- Make the smallest useful automation.
  1. Validate the inputs.
  2. Run the operation.
  3. Report the outcome.
- Leave enough context for the next person.

A checklist is useful when the order matters less than whether each step is complete:

- [x] Keep the reading column comfortable.
- [x] Use the same sharp edges throughout.
- [ ] Check the examples on a narrow screen.

## Code blocks

Code uses a neutral surface, one restrained accent, and the same monospace family as the interface. Language labels and filenames belong in the header. The copy control copies the code, not the header.

```python title="automation.py" {4-6}
from pathlib import Path


def collect_notes(directory: Path) -> list[Path]:
    # Return a predictable order for repeatable builds.
    return sorted(directory.glob("*.md"))


notes = collect_notes(Path("content/posts"))
print(f"Found {len(notes)} notes")
```

### Long lines and plain text

Long source lines stay on one line and scroll inside their code block. They should not widen the article or push the contents navigation out of place.

```text title="example.log"
2026-10-15T09:30:00Z INFO workflow=content-validation environment=development source=content/posts result=success message="All published entries passed validation and are ready for the next build."
```
